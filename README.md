# ⛔⛔⛔ 永远的痛：D6 床上那人——前後将近四十个小时、三千多万 token、九轮，没有结果 ⛔⛔⛔

> 一件事耗了将近四十个小时，这件事本身就极可怕。病根是**方法**：开头造出来的东西不过硬，後面拿修去救——质量烂的大厦，後面再怎么修也会塌；同一个法子（挑刺→修→再验）跑了九轮，没有一处到点必停、必裁、必换。（1008 作者令：作为永远的痛，时时刻刻拿出来当教训；每开一个方法都先参考这件事。）
>
> **第一招，也是最要紧的一招：在开头就造到满分。** 写剧情、做逻辑闭环，一开始就尽全力造到绝对的 100 分——挑不出任何毛病、质量绝对过硬，大厦就不会塌。造时就要把全书对一遍账：新案里每一样物、每一个日子，都把正文里所有提到它的地方查出来，逐处定「留／删／改」，写进案里——⛔留一句与新案相抵的旧文（D6 六审验·1 之病即此：263 章「粮房两年」那一串没删）。造出来是垃圾的，**毁了重造**，取其精华、去其糟粕，⛔修。
>
> **第二招：止损闸（`工具/工作流账.py`，`--查` 入全测）**——它是为了**把事情解决**，不是为了撂下：
> 1. **开法四问**：①时限（几小时内出结果）②停止线（到什么数就算成）③重造之法（到点没成，怎么毁了重造、换成什么法）④**有效与效率**——凭什么确定此法绝对有效（有据，⛔凭感觉）？预估几时、多少 token？有没有更省而同样有效的法？取最省之有效者（1008 作者令：「这一周的 token 又快用光了，干了一堆无用功；做一件事先确定方法绝对有效，再看效率——既要完美，又要花的时间少」）。缺一拒开。
> 2. **到点必裁**：逾时限而未裁，全测即红、推不上去。只有三种裁：**取**（达标）／**重造**（毁了重造，取其精华，换法，重起计时）／**续**（至多一回）。
> 3. **⛔烂尾**：没有「守原了事」「不干了」这一出口——留下烂摊子，工作就进行不下去了。重造两回仍不达标 → 报作者商量新路，仍⛔撂下。
> 4. **两次不成即换法；只看产出不看过程**：每一轮之後亲看数，两轮不见涨立停、换法。忙了几小时不等於有进展。
>
> **★★★虫洞之律（开发方法之第一法则·最高优先级·1008 作者令）**：一切机制、一切方面都随时更新、随时进化，⛔一成不变；兼具灵活与实时进化——而开发任何方法，第一法则就是虫洞：像从地球中间挖一条洞直通对面——**比绕地球一圈更快、更省，效果还更好**。选任何方法，先找这条虫洞：①这件事的本质是什么？②直通它的那条路在哪？③这条路是否**效果更好、且花费更少**——两样都满足才用；只满足一样，接着找。⛔笨办法（绕地球一圈：堆人、堆轮、反复通读、开放式挑刺），既费 token 又无效。随时拿踩过的坑（下列「坑之账」）对一遍，灵活应变，随时开发出更好的虫洞之法。**进化之检**：新法替旧法，须同时满足——效果比旧法更好（剧情更好看、闭环更完美）、花费比旧法更少；⛔为新而新。
>
> **坑之账（每开一法对一遍；新坑随踩随添）**：①D6 九轮挑刺→修→再验，将近四十小时无果（开放式之审永不收敛→改用 grep 全数＋只判所留）｜②修案席逐行重读正文，十八分钟转录涨 1.5MB（机器能找的让模型找）｜③设计档长到 160KB，每席读一回都是钱（档要短）｜④多席反复通读同一大档（一席带料造到满分）｜⑤推送排队脚本用 pgrep 认错自己，空转一小时（用锁不用猜）｜⑥只数档数不读档尾，误报病册全成（核收束）｜⑦存底环容器重启即死、四小时未存（每回开工先重开、看日志）｜⑧D6 判席三席用了约 74 万 token，超所估三倍——席多读了上下文（判席令里写明只看该行上下各三行，并在令里给 token 之数；估时按实测×1.5）。
>
> **★方法之律（1008 作者令：方法先要绝对有效，再要最高效——花一块钱办成，且比花一百块办得更好；每个 token 都花在刀刃上，⛔挥霍）**：
> 1. **机器能做的全交脚本**（grep、对账、数数、核行号、滤已处之行），零 token；模型只做两件事：**造**与**判**。
> 2. **造**：一位最强之席，带足所需之料，一次造到满分；⛔多席反复通读同一份大档。
> 3. **判**：只判脚本筛出的那几行、那几处（如 `工具/对账预筛.py`）；⛔开放式挑刺——每轮重读整案、轮轮有新刺、永不收敛，D6 之痛即此。
> 4. **档要短**：设计档只写定案表与改处，⛔长篇论证（每读一回都是钱）。
> 5. **开法前估成本**（几时、多少 token）；长跑之席每半时看一眼产出，空转立停（1008 实例：D6 修案席十八分钟里转录涨 1.5MB，全在逐行重读，当场停）。
> 6. **叫绝之拍（好看朝满分之法·1008 总编辑裁）**：每份设计须列三至五拍「拍案叫绝」——何章、何物、读者为何倒吸一口气——并与全书已有最强之拍对标（如斗沿那一圈牙印、东头「我没应」）；够不上就重造，⛔补。
> 7. **以文为准**：设计是骨，满分落在每一章的执行上——设计里的叫绝之拍，写章时须在页上落到顶（一章.js 之「连读检」以读者位专核这几拍：落没落、哪里走神），⛔只在设计里叫绝。
> 8. **方法账（虫洞之实证）**：每法跑完即记 `设定/方法账.md`（预估、实耗、时长、成果）；开法先查同类最优者起步；新法须在账上「效果更好且花费更少」方许替旧法——⛔凭感觉称更好。
>
