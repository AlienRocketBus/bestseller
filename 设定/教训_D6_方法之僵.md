# 教训·D6 床上那人：方法之僵（1007 作者令，凡做任何任务皆须先读）

> 作者原话：「这在什么呀？制度化的僵硬和死板，导致我们没有办法去做出新的创新，导致问题也没有办法解决……既然方法不行……那我们就要考虑去创新了。」
> 「大家总想着骑马……以为是速度最快的方式，你想用骑马方式在一个小时跑100km，那根本就不可能……後来人们创造了汽车。」

## 一、发生了什么
- 题：暗线闲屋里床上那人是谁。
- 二审至五审，同一方法（剧情庭式「验」：一份主案→挑刺→修案→复评→门，三轮）反复跑了**九轮以上，三十多个小时，约 3000 万 token**，没有一次过门。
- 立得住分数在 3.5—5.6 之间来回，**不收敛，甚至变差**；每轮都把失败归为「这一轮修得不够」，下一轮照旧的方法再跑。

## 二、坑在哪（根本原因：方法本身有问题，而我们死守方法）
1. **把方法当成不可动的制度**：剧情庭之门、修案之式、圣经之条，都被当作铁律；问题解决不了时，只想「再跑一轮」，从没问「是不是方法错了」。这就是骑马跑一百公里。
2. **修案＝补窟窿**：修案席每轮看到刺就现编一个新由头去堵，新由头又生新刺；方法的形状决定了它只能补，不能升级。
3. **一席设计、众席挑刺**：设计只靠一个席位、几分钟写成，然後花上千万 token 去挑它的刺——力气全花在验上，没花在造上。**修的过程最重要，我们把它做成了最轻的一环。**
4. **自设禁区**：总编辑自己在圣经里立了作者从未下过的禁令（「⛔以死地抽寿元释年岁」），各席当成明禁，把可用之路堵死。
5. **把旧文当地基死贴**：一百多章已写之句被当成不能动的墙，新设计只能在缝里钻；其实大升级本就要重写这些章，可以整块拆了重造。
6. **总编辑反应太慢**：三审後已看出不收敛，却拖到五审、六审才换法；守了流程，丢了目的。

## 三、以後怎么做（铁则）
1. **同一问题，同一方法，两次不成即停**：第三次之前，必须先问「是不是方法错了」，并至少拿出两种**不同形状**的新方法来比，择优再做。⛔第三次照旧法跑。
2. **先造後验**：凡改剧情，力气先花在设计——多席独立设计、对抗审、合成、闭环自查——做到自己认为完美，再交验。⛔拿半成之案去验、靠验来补。
3. **升级，不是补窟窿**：修不好就整块拆了重造；设定不好就弃、另立（合本书背景即可）；旧句挡路就改旧句。
4. **一切皆可改**：圣经、律、裁、门、流程、工具、席位都是工具；唯一不改的是「让这本书成为中国第一、剧情最好看」。⛔自立禁区。
5. **方法本身要不断升级**：每做完一件大事，回头问「下次有没有更好的方法」，把答案写进本档或常令。
6. **花费即信号**：一件事花了预期的两倍时间或 token 还没成，立即停下、复盘方法、报作者。

## 四、这次已换的新法
D6 由「式验九轮」改为：**三位顶尖设计席各自独立做升级设计（小说家／剧本师／逻辑闭环师）→ 每案两席对抗审（逻辑闭环、好看）→ 合成席取最强之骨、嫁接诸长、根治诸刺、闭环自查 → 再交验**（脚本 `工具/席/D6升级设计.js`）。若此法仍不成，再换法，⛔回到旧法。


## 附·推送之锁（1007，同类之坑）
- **坑**：为「等前一次推送结束再推下一批」，写了排队脚本，用 `pgrep -f "git push -u origin"` 判有无推送在跑——排队脚本自己的命令行就含这串字，於是永远认为「还有推送在跑」；两个排队脚本互等，空转一个多小时，一次没推。没花 token，但耽误了上云。
- **根**：拿「进程名」猜状态，猜的人自己也在名单里；且写完没试一次就放着跑。
- **治**：立 `工具/推.py`——用文件锁（进程死锁即放）判状态；锁被占只登记不等待；被拦即停不空转；自测 5/5。⛔再自写排队脚本。
- **通则**：凡要「等某事结束」，用锁或明确的完成信号，⛔靠 ps/pgrep 猜；新写的後台小脚本，**先亲试一次、看它真的会结束**，再放手。

## 永远的痛·止损闸（1008 作者令：「将近四十个小时没有结果，这件事本身就极可怕；一定要有强大的应对机制，而且这机制是要把事情解决，不是撂下烂尾；最佳之法是在开头就造到完美」）

**为什么将近四十个小时没人喊停**：每一轮看起来都在「做事」：挑刺、修、再验，席位都很忙。但没有一个地方写着「几点必须出结果」「出不了结果就怎么重造」。忙就被当成了进展。根子更在前头：开头造出来的不过硬，後面拿修去救。

**第一招（最要紧）：开头就造到满分。**
- 写剧情、做闭环，造时就尽全力到 100 分：挑不出任何毛病。质量过硬的大厦不会塌；烂的大厦後面怎么修都会塌。
- **造时即全书对账**：新案里每一样物、每一个人、每一个日子，用 grep 把 `正文/` 里所有提到它的行查出来（写明所用之词与命中数），逐处定「留／删／改」，写进案里的「全书对账表」。⛔留一句与新案相抵的旧文。（D6 六审验·1 之致命刺即此：263 章「粮房两年」一串十余行未删。）
- 造出来是垃圾的，**毁了重造**，取其精华、去其糟粕；⛔修。只有骨已极好、只剩执行之瑕的，才修，且限一回。

**第二招：止损闸（`工具/工作流账.py`，`--查` 入全测）。它为的是把事情解决，不是撂下。**
| 环 | 做法 | 机器怎么逼 |
|---|---|---|
| 开法三问 | `--开 W? 时限 "停止线" "重造之法"`：先印本痛与三问，答全才开 | 缺一拒开；凡「进行」之件缺 起／时限／停止线／换法 → 全测红 |
| 到点必裁 | 逾时限 → `--裁 W? 取｜重造｜续 "由"` | 逾时而未裁 → 全测红、推不上去 |
| ⛔烂尾 | 没有「守原了事」之出口；原文果真已达标，以「取」裁之并写由 | `--裁 … 守原` 拒 |
| 续至多一回 | 续一回之後再逾时，只许 取／重造 | 再续拒 |
| 重造两回仍不达标 | 报作者商量新路，仍⛔撂下 | 第三回重造拒 |
| 印即提醒 | `工作流账.py` 每回开头一跑，即印本痛，并印每件「已跑几时／时限几时」 | 逾时之件印 ⛔⛔ |

**人的那一半（机器管不到，总编辑亲守）**：
- **只看产出，不看过程**：每一轮之後亲看数（好看、立得住、判胜）。两轮不见涨，立停、换法。
- **两次不成即换法**：同一问题、同一法子，两次不成，第三次⛔照旧。
- **式验之轮数**：剧情庭式验由三轮减为两轮（一回修、一回验）。`工具/剧情庭.js` 待 D6 本回式验跑完再改，此刻改它会使 resume 之缓存全失。

**首用（1008 05:50，W15 D6 六审式验）**：验·1 出数：好看 8.5（现文 4.5），立得住 4／3.5，四席皆判未胜。致命刺俱在执行层（263 粮房两年之漂未删、阿婆吃食一链），诸席皆判骨无致命，係好车之执行瑕。闸当场补上：时限 7 时（自 02:31 起）。停止线是验·2 出数即停跑，⛔修案·2、⛔验·3；达标即取。不达标则总编辑亲治：全书对账、逐刺根治，限 3 时，再一回验。⛔守原了事。
