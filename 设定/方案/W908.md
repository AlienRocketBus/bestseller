## 运营之机

> 设计要旨：运营之卡由 GitHub 零 token 自算；读 Actions 之迹与 报/；每流每维之分随跑而新；扣分入进化之账；告警走既有之路、⛔另立；写者唯一。

- **器**：立 `工具/运营卡.py`，唯算卡（同名已查：工具/ 无「运营」之器，坑18）。
  - 读报经 推报.诸报（推报.py:233），写报经 推报 --落，⛔另造报之读写。
- **跑处与写者（唯一）**：唯 autopush.yml 报步。
  - 位置：`推报 --写` 之後、`--落` 之前。
  - 令：`timeout 60 python3 工具/运营卡.py --算 --出 "$D" --摘 >> "$GITHUB_STEP_SUMMARY" || echo 卡·算败`。
  - 卡随本跑之报同一提交入 备份/报。写者册「报」族之唯一写者 推报.落 不增。
  - autopush 并发组只容一跑（autopush.yml:26-28），卡之写自串、无竞。
  - 巡、演练⛔写卡。
- **读**（零 token；GITHUB_TOKEN 之 actions 权，autopush.yml:25 已有 write）：
  - ① Actions：四流各近百跑，增量取——卡记末处理之 run id，只取新毕者之 jobs；以 (run_id, attempt) 为键，⛔以 ref 为键（坑62）。環之毕跑取其志末「環毕：N 巡（rc：…）」行（巡.yml「環毕」之印），得 rc 之布。
  - ② 报/：报/推/*.json（果、因、试、主前→主後、片秒、冲突）、报/演/*.json（果、期）、报/器红账.json、报/均秒.json。败因之史取 备份/报 之 git log（⛔另立 jsonl）。另读 备份/巡印、备份/巡应（鲜、rc）。
  - ③ 哨 PR #1 之言，即唤之史（键、时）。
  - ④ 静：.github/workflows/*.yml 之 uses 钉否、permissions、summary、步限、runtime。借 推报 之 YAML 子集析（推报.py:689），⛔另写析器。
- **算**：
  - 每流×八维，照「满分之尺」之扣类逐类计，每扣带据。
  - 首算以 备份/报 之 git log 补史（报每 ref 覆写，旧果取其旧版）。
  - #1—#53 日志已 404，标「不可考」，⛔计 0（坑27）。
- **写**：
  - 报/卡.json（机读）：流、维、分、扣〔键、类、首见、末见、次、据、治〕、算於、末 run id。
  - 报/卡.md（人读，GitHub 网页直观）：一流一行之表、扣之要、近十卡之分趋（取 git log）。
  - 本跑 summary 印卡之表与本跑之增减。
- **扣入进化之账**：卡之「扣」即运营之进化账。
  - 首见即记；治即销，移「史」、留末据；同键销後复见即标「复发」。
  - 复发，或同类扣及 ≥2 流 → 报之读印「⚠ 运营之扣复发」。总编辑照立坑於 设定/方法坑账.json（既有之进化账），⛔另立坑账。
- **告**（走既有之路，⛔另立）：

  - Actions API 之读：卡之源，零 token，公仓分钟不计。
